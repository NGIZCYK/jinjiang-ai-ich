## 1. Summary of Work Completed This Week

- **模块 1｜MVP 信息架构**：将产品明确为“酒店住前/住中场景的 AI 苏绣体验助手”，形成七屏路径：登录/注册、首页、婉娘导览、沉浸非遗角、内容工作台、我的体验、商业分析看板。路径对应住客从了解文化到生成建议、预约体验，再由运营查看转化与 ROI 的完整闭环。
- **模块 2｜三项核心功能**：定义并分层为：①数字人“婉娘”进行苏绣问答、推荐与情感标签；②沉浸非遗角与内容工作台，将工艺认知转成行程/推广文案；③预约和商业分析，将住客操作连接到客群分层、收入情景与 ROI 展示。登录只作为基础设施，不计入三项核心业务功能。
- **模块 3｜技术路线与可行性**：确定前端采用 Vite + React + TypeScript + Tailwind，状态与演示数据采用 Zustand/localStorage；导览层保留 DeepSeek 兼容接口，并在无 Key 时提供本地演示回复；沉浸层采用 A-Frame/WebXR 薄场景；分析层采用 Python、pandas、scikit-learn 的合成样本与方法说明。该组合的目标是让课堂演示在没有真实酒店 PMS、支付系统或 API Key 时仍可跑通。
- **模块 4｜文化内容边界**：整理苏绣的地域、工艺关键词、常见题材、体验课流程和酒店结合点。团队决定在所有原型文案中标明“整理自公开资料，正式商用需授权与传承人/版权审核”，不把合成价格、模拟经营数据或 AI 补充知识误写为真实酒店信息。
- **模块 5｜看板与下一步拆分**：建议按“导览知识库、首页/导航、沉浸场景、内容生成、预约闭环、分析脚本、测试计划、证据归档”建立责任卡。请用实际看板统计替换：启动 `[X]` 张，进行中 `[Y]` 张，完成 `[Z]` 张。

## 2. Challenges Encountered

1. **技术链路依赖风险**：真实 LLM API、网络环境与 3D 场景加载都可能在演示时失败。团队需要从第二周开始设计可独立运行的本地回复、静态资源和 2D 回退说明，而不是在最后一周临时补救。
2. **“功能多”与“闭环深”的取舍**：七屏并不等于七个核心功能。若每页只放静态介绍，会在 Functionality & Problem-Solving 维度失分；因此每个核心模块都必须有可输入、可处理、可产出或可追踪的行为。
3. **协作接口不清晰**：内容、设计、前端和分析若各自推进，容易出现命名不一致或同一数据无法跨页面使用。需要把每个页面的输入、输出、负责人和验收条件写到看板卡片中。
