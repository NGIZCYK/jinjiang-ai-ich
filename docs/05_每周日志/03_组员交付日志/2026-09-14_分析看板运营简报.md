# 分析看板改动日志

记录日期：2026-09-14  
范围：仅限“分析看板”及其与“婉娘导览”之间的匿名经营数据反馈，不涉及其他同学负责的页面功能。

## 1. Python 分析层接入网页

- 将 `analytics/analyze.py` 从手写 numpy 聚类改为 `pandas + scikit-learn KMeans(k=3)`。
- 脚本生成 1,200 条不含姓名、联系方式等个人信息的课程合成样本，并输出三类客群：文化体验型、亲子休闲型、商务快捷型。
- 脚本一次运行会同时写入：
  - `analytics/output/analytics_snapshot.json`：分析层原始产物；
  - `web/public/analytics/analytics_snapshot.json`：网页实际读取的快照。
- `AnalyticsPage.tsx` 改为请求 `/analytics/analytics_snapshot.json`，删除了原先前端固定的 `MOCK_ANALYTICS` 依赖。
- `analytics/requirements.txt` 新增 `scikit-learn>=1.4.0`。

## 2. 用户分群与筛选

- 分析看板新增四个筛选条件：目标客群、最低停留时长、最低客房消费、最低非遗兴趣指数。
- 看板根据筛选后的匿名样本，重新展示样本数、客群占比、平均停留时长、平均客房消费和兴趣指数。
- 筛选比例会映射为下方经营模拟中的“可触达客群规模”，使客群分析和营收计算使用同一组条件。

## 3. 营收与 ROI 决策模拟

- 保留基线、轻体验包、主题房加体验课三个方案预设。
- 新增可修改参数：月度酒店客量、体验转化率、体验课单价、主题房客单提升、月度基础营收、每月场次、每场容量、单客材料/服务成本、月固定运营成本和一次性启动投入。
- 页面实时计算预估需求、容量、实际可承接预约、体验课收入、主题房增收、月度成本、月度贡献、收入指数、12 个月 ROI 和回本期。
- 所有金额和数据明确标为课程经营假设或合成数据，不表述为真实锦江经营结果。

## 4. 可执行经营建议

- 原有的泛化提示升级为“建议试点 / 建议扩大 / 暂缓投入”三类经营判断。
- 新增执行卡片，包含：
  - 目标客群、每周场次、每场容量和 4 周试点周期；
  - 目标转化率、预估承接人数、需同步记录的指标；
  - 扩大门槛：转化率、到课率、ROI 和匿名导览意向数量；
  - 暂停条件：连续低转化或月度贡献不为正时，复核价格、容量和成本。

## 5. AI 与业务闭环

- 在 `GuidePage.tsx` 中，用户向婉娘发送消息后，会用规则提取匿名标签：工艺/体验/文化兴趣、可用时长、预算、独自/家庭/商务同行类型和情感标签。
- 标签只保存在浏览器本地 `jj_guide_signals`，不保存用户原话、姓名、邮箱或联系方式；清空导览对话时同步清空标签。
- 分析看板新增“婉娘导览的匿名意向汇总”，展示兴趣、时长、预算和同行偏好聚合结果。
- 新增 `/api/analytics/brief` 本地接口。点击“生成 AI 运营简报”时，网页只发送聚合指标、筛选条件和 ROI 假设给本地 Vite 服务；服务端使用既有的 `DEEPSEEK_API_KEY` 调用 DeepSeek。
- DeepSeek 返回结构化运营简报：标题、试点/扩大/暂停决定、理由、行动项、扩大门槛、暂停条件和数据限制。接口提示模型不得把合成样本说成真实酒店经营数据。
- 新增 `web/src/lib/analytics.ts`，负责调用接口和验证结构化简报数据。
