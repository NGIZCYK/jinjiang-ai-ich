## 成员原始工作陈述

### 1. 项目启动与课程要求核对

- 确认本地开发地址为 `http://127.0.0.1:5180/`，课堂演示应从首页进入功能页。
- 对照 ENT207 要求，聚焦“真实输入 → AI 处理 → 输出”的数字人导览链路。
- 保留正常启动与首页跳转方式；此前用于单独打开导览页的临时文件不作为交付内容。
- 记录中提到新增 `open-immersive.cmd` 便于本机打开沉浸非遗角。

### 2. DeepSeek API 对话接入

- 记录称：在 Vite 本地服务中增加同源聊天状态与聊天接口，由服务端环境变量读取密钥，浏览器不接触密钥。
- 记录称：前端可显示 DeepSeek 或本地演示模式，接口异常时回退到本地回复。
- 记录称：补充 `.env.example`、README 与 `.gitignore` 说明，真实密钥仅放在未提交的本机 `.env`。

### 3. 婉娘人设与多轮导览优化

- 将人设定位为“温婉礼宾为主、江南叙事为辅”，避免生硬的技术化拒绝语。
- 对超出当前素材范围的景点、路线或实时价格，以礼宾语气提示住客由前台结合当天情况确认。
- 每次回答最多追问一个会影响安排的问题。
- 将已有聊天记录随新问题传递，以理解同行人数、时长与预算等上下文。
- 记录中描述三类受控动作：生成体验行程、生成预约草稿、建议进入沉浸非遗角；动作参数在本地校验，不能直接创建真实预约。
- 为避免重复，提示模型参考最近三条导览回复，不在用户补充时长或预算时反复讲解相同的工艺知识。

### 4. 清空聊天记录

- 在导览聊天区增加清除对话入口。
- 清除本地保存的历史记录、取消浏览器语音朗读，并回到婉娘初始问候，以支持下一位演示用户从干净上下文开始。

### 5. 成员记录中的验证声明

- 进行实际 `/api/chat` 请求，验证 DeepSeek 能返回不同自然语言回复，并生成行程、预约草稿和沉浸角动作。
- 检查导览页面状态、行程卡片、预约草稿与清除对话按钮。
- 执行 TypeScript 编译检查与 Vite 生产构建。
