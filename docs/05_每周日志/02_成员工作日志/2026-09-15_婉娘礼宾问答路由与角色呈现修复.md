# 成员工作日志｜婉娘礼宾问答路由与角色呈现修复

## 1. 今日问题与目标

本轮复核发现，婉娘礼宾虽已具备 DeepSeek 接入、流式文字和数字人舞台结构，但实际体验仍有四类问题：

1. “第一次去苏州有哪些推荐景点”等城市问题被误判为项目体验问题，回复套用了 90 分钟苏绣主题行程；
2. 回答中会暴露“未匹配知识卡”“项目专属知识”等内部路由措辞，破坏礼宾角色的自然感；
3. 角色形象偏古装/游戏立绘，且页面把静态图、浏览器朗读误呈现为 Live2D、Azure TTS 已就绪；
4. 一键启动可能复用旧的 5181 端口进程，造成“代码已改但浏览器仍显示旧版本”。

本轮目标是把婉娘从“受限项目问答工具”调整为“以苏绣和苏州为专长、同时能回答一般问题的文化礼宾”，并让界面只展示当前真实具备的能力。

## 2. 关键判断与改造内容

### 2.1 问答路由与苏州知识

- 新增独立意图层，区分苏绣工艺、项目行程、项目预约、苏州景点、苏州饮食、苏州交通和一般问题；
- 将“推荐”从项目行程的宽泛触发词中移除，避免普通旅游提问被强行导向课程原型；
- 对“虎丘区”和“虎丘山景区”进行消歧：前者按行政区理解，后者按景点理解；
- 增加苏州城市基础资料与核验来源，为模型提供景点、交通、饮食和文化背景；
- 重写提示词约束：先直接回答问题，不暴露内部检索/路由术语，不虚构酒店、工坊、预约名额或已上线服务；
- 广泛常识问题继续交给 DeepSeek，而非被本地知识范围拒绝。

### 2.2 DeepSeek SSE 与降级链路

- 新增 `/api/capabilities`，由服务端返回当前聊天、TTS、角色模型的真实能力状态；
- 增加版本标识 `2026.09.15-guide-v2`，启动器据此判断浏览器连接的是否为最新服务；
- 同时兼容 SSE 与 JSON 响应，并识别误返回的 HTML，避免旧服务或代理异常被当成模型正文；
- 对流式片段做小批量缓冲，减少逐字闪烁，同时保留实时反馈；
- 在线服务不可用时进入本地兜底，并保证兜底文本不泄露内部诊断语句。

### 2.3 角色形象与页面呈现

- 生成并接入新版透明背景静态角色图 `wanniang-concierge-v2.png`；
- 角色方向改为当代江南文化礼宾：黛青与暖白制服、低密度苏绣纹样、克制首饰，减少古装、游戏感和无关线材道具；
- 桌面端重新平衡角色舞台与会话区比例，缩窄左侧舞台并扩大正文阅读区域；
- 清理聊天区过强的竖向网格，修复状态文字被全局样式挤成竖排的问题；
- 将“知识卡”改为更符合用户心智的“参考与核验”，降低后台系统术语感；
- 当前未配置 Live2D 模型时明确显示“静态礼宾”，未配置 Azure 时明确显示“浏览器朗读”。

> 新角色图属于 AI 辅助生成的视觉原型，不等同于最终授权商用形象，也不是可直接驱动的 Live2D 分层模型。

### 2.4 Live2D 与语音状态真实性

- 移除空 Canvas、500ms 假加载和静态图模拟张嘴等容易造成“功能已完成”误解的处理；
- 建立真实 Live2D 运行时适配边界：只有模型完成挂载并返回控制器后，才从静态图切换到 Live2D；
- 模型缺失、WebGL 丢失或运行时失败时，静态角色持续可见且聊天功能不受影响；
- TTS 队列增加 `idle / synthesizing / playing` 阶段以及运行代次保护，避免停止后旧音频继续播放；
- 角色只在音频实际开始播放后进入 speaking 状态，终止时同步取消队列、浏览器朗读和动效。

### 2.5 一键启动稳定性

- 启动脚本先核验 `/api/capabilities` 的版本，不再只凭端口已占用就认定服务可用；
- 仅在确认 5181 端口属于本项目 Vite 进程后才结束旧进程，降低误杀其他服务的风险；
- 完成生产构建后在后台启动预览，并由批处理文件在失败时保留终端错误信息。

- “第一次去苏州有哪些推荐景点”识别为苏州旅行，而非项目体验行程；
- “虎丘区有哪些景点”进入苏州旅行并触发行政区消歧；
- “帮我安排 2 小时苏绣体验”识别为项目行程；

- 一般知识问题保持通用问答能力；
- 在线 DeepSeek 可直接回答苏州问题，英文提问的英文回复未残留中文；
- 离线兜底可用，未再出现“未匹配知识卡”等内部措辞；
- SSE 响应包含 `meta / delta / done`，首页、导览页和新版角色图片均返回 HTTP 200；
- 连续执行启动脚本时可识别已运行的最新预览，不重复启动旧服务。

## 6. 当前边界与下一步

1. 当前人物是高保真静态礼宾原型；要实现 Live2D，仍需原创分层 PSD、Cubism 建模授权和前端运行时；
2. 当前语音为浏览器 TTS；要实现句子级 Azure TTS + Viseme，仍需有效凭据、服务端保护和实测；
3. 苏州景点开放时间、票务、交通和预约属于动态信息，正式演示应提示用户以官方最新公告为准；
4. 下一轮应优先完成桌面/平板/手机截图与录屏，再决定是否投入 Live2D 制作，避免把技术展示置于核心礼宾体验之前。
