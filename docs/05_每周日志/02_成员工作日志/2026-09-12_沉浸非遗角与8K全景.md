# 成员工作日志｜沉浸非遗角与 8K 全景优化

## 归档说明

本日志记录 2026-09-12 对“沉浸非遗角”的实际优化过程，范围包括苏绣场景重构、全景资源增强、热点与展签交互、A-Frame 相机切换修复、高清纹理加载和中英文展签内容。日志只陈述当前项目中已经实现和核验的内容，不包含未发生的用户测试、导师建议或看板记录。

## 一、当日目标与问题定义

本次迭代集中解决四个可观察问题：

1. 原沉浸场景左侧存在电子设备，与“非遗为主”的空间叙事冲突。
2. 原全景图分辨率和局部细节不足，放入 360° 球面后出现明显模糊。
3. 场景内悬浮文字牌、准星和提示层遮挡陈设，影响观看。
4. 点击不同展签时，说明文字会变化，但相机视角无法稳定转向对应展项。

对应的产品目标是：把该模块从“带热点的酒店背景图”改造成一个可连续完成“观绣—识线—试针”的苏绣典藏廊。

## 二、当日完成内容

### 1. 重构纯非遗全景场景

- 移除电子屏、数码设备、二维码和现代接待设备。
- 将《花下双猫》设为中轴主展画，形成清晰的第一视觉中心。
- 左侧增加传统绣架、绣绷、丝线架、针具、底稿与花瓣练习样本。
- 右侧增加丝线与针法百宝阁、综合色谱、绣样、抽屉柜和双面绣架。
- 两端补充苏式花窗、江南园林、盆景、太湖石、屏风与茶席，使场景兼具酒店主题空间与非遗典藏氛围。
- 保持无人物、无标识文字、无现代科技设备的展陈边界。

### 2. 优化场景内外的信息层级

- 删除场景内的大号悬浮标牌和常驻中心准星。
- 将三个交互点改为小型“金线结点”，并保留较大的透明点击区，兼顾简洁与可操作性。
- 将完整展签、当前展项和“回到主展画”按钮移到全景画面外，避免遮挡展品。
- 展签调整为三个连续动作：
  - 01 观绣：《花下双猫》主展画；
  - 02 识线：丝线与针法百宝阁；
  - 03 试针：传统绣架与起针台。
- 完善三项展签的中英文标题、工艺解释、建议观察、住中延伸与内容来源说明。

### 3. 修复展签视角无法切换的问题

经代码和本地 A-Frame 1.5 实现核对，问题原因是：

- 旧方案在点击展签时增加 sceneVersion，销毁并重新创建整个 A-Frame 场景。
- 新场景虽然向相机写入 rotation，但 look-controls 每一帧都会使用内部 yawObject 和 pitchObject 覆盖相机角度。
- 因此展签状态已经变化，但相机很快回到原方向；同时场景重建还会重新显示低分辨率预览图。

本次处理：

- 取消点击展签时重建整个场景的做法，使全景纹理和 WebGL 场景保持常驻。
- 新增独立的 focusRequest，让重复点击同一展项和“回到主展画”仍可重新触发转向。
- 直接同步 look-controls.yawObject 与 pitchObject。
- 使用约 620 ms 的缓动动画平滑转场，并选择最短旋转路径。
- 用户开始拖动画面时取消尚未结束的自动转场，避免系统与用户争夺控制权。
- 重新校准三个展项：

| 展项 | 水平角度 yaw | 垂直角度 pitch |
| :--- | ---: | ---: |
| 《花下双猫》主展画 | 0° | 5° |
| 丝线与针法百宝阁 | -90° | 0° |
| 传统绣架与起针台 | 128° | -5° |

### 4. 制作并接入高清全景资源

- 使用内置图像生成能力对原场景进行细节增强，重点补充刺绣丝线、木雕、铜件、石材、园林植物和绣具纹理。
- 保持 2:1 等距柱状全景比例、相机位置、空间布局和左右接缝关系不变。
- 使用本地 OpenCV EDSR 4 倍超分模型按块处理图像，并使用环向包裹边界降低左右接缝断裂风险。
- 生成以下非覆盖式 v4 资源：

| 资源 | 尺寸 | 用途 |
| :--- | :---: | :--- |
| lobby-heritage-360-preview-v4.webp | 1024 × 512 | 加载封面 |
| lobby-heritage-360-4k-v4.webp | 4096 × 2048 | 小屏或不支持 8K 的设备 |
| lobby-heritage-360-8k-v4.webp | 8192 × 4096 | 桌面端沉浸场景 |

- 桌面端在 WebGL 最大纹理尺寸支持 8192 时直接加载 8K，不再依赖浏览器可能缺失的 deviceMemory 参数。
- 手机宽度默认回退 4K，降低显存不足、加载过慢或浏览器崩溃的风险。
- 预览图只作为加载封面，不再先映射到全景球，避免进入和切换时出现“先糊后清晰”。
- 高清纹理载入后启用设备支持的最大各向异性，改善侧面展柜和斜视区域的纹理表现。

### 5. 形成“输入—处理—输出”功能链路

| 环节 | 当前实现 |
| :--- | :--- |
| 输入 | 用户点击画面热点、下方展签或“回到主展画”，也可手动拖动环顾空间。 |
| 处理 | React 更新当前展项；相机控制逻辑计算目标 yaw/pitch，并同步 A-Frame look-controls 完成平滑转向。 |
| 输出 | 视角对准对应展项；当前展签、详细解读、观察建议和住中延伸同步更新。 |
| 回退 | 桌面不支持 8K 时加载 4K；A-Frame 异常时保留下方二维展签内容。 |

## 五、遇到的挑战与应对

| 挑战 | 影响 | 应对方式 |
| :--- | :--- | :--- |
| A-Frame 相机属性被 look-controls 覆盖 | 展签文字变化但视角不动 | 改为控制内部 yaw/pitch，不再依赖重建场景和相机 rotation 属性。 |
| 8K 文件只是普通插值放大 | 文件尺寸变大但局部细节没有真实增加 | 先做生成式纹理增强，再用 EDSR 模型按块超分。 |
| 每次切换重载低清预览图 | 操作时反复出现模糊画面 | 场景常驻；预览图只作为首次加载封面。 |
| 8K 纹理显存占用较高 | 部分手机可能加载失败 | 桌面端 8K 优先，手机与低能力设备回退 4K。 |
| 自动转场可能与拖拽冲突 | 用户操作感不稳定 | 用户开始拖拽时立即取消转场动画。 |
