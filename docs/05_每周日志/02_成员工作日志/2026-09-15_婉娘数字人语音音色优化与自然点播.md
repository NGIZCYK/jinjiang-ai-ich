# 成员工作日志｜婉娘数字人语音音色优化与自主点播升级

## 1. 今日问题与目标（Why）

在婉娘数字人导览的实际复核测试中，发现语音朗读环节存在影响奢华文旅质感的明显痛点：

1. **语音语气过于机械呆板**：
   在未配置外部商业级语音服务（如 Azure Speech Key）的本地开发/测试环境下，系统默认降级至浏览器原生 `SpeechSynthesis`。在 Windows 操作系统中，若未显式指定音色，浏览器会直接调用 Windows 早期的离线 SAPI 引擎（如 `Microsoft Huihui Desktop`），发音扁平生硬、断句怪异，充满“2000年代老旧 GPS 导航”的机械冰冷感，严重破坏了江南非遗文化礼宾温婉、知性、尊崇的人设调性。
2. **朗读包含大量技术代码与符号噪点**：
   大模型流式输出的正文中包含 Markdown 语法符号（如 `**加粗**`、`# 标题`、`- 列表减号`、`[链接]`）以及括号内学术溯源标签（如“（文献线索）”、“（工艺经验）”）。原系统直接将原始字符串送入 TTS 引擎，导致合成语音将“星号、星号、减号”一并读出，产生极低级的念稿事故。
3. **住客缺乏即时的听觉掌控权（被动噪音困扰）**：
   原系统唯一的“自动朗读”开关被深埋在 `<details>` 折叠抽屉（“导览设置”）内，住客无法在对话顶栏一目了然地识别当前语音状态，也无法在需要安静阅读时一键静音；单条回答下方的操作按钮为生硬的“朗读回答”，缺乏文化礼宾的交互温度。

本轮目标：**采纳「方案一」，在 0 外部采购成本、无需商业 API Key 的前提下，彻底根除机械音违和感，实现口语化净化与高雅点播控制。**

## 2. 核心技术改造与工程落地（What）

### 2.1 智能优先匹配 Edge / Chrome 原生超自然在线音色（`browserTts.ts`）
- **核心机制**：现代 Chromium（Edge、Chrome）在连接网络时，浏览器内部免费集成了微软 Azure 级的高保真云端神经网络女声（如 `Microsoft Xiaoxiao Online (Natural)` 微软小晓、`Microsoft Xiaoyi Online (Natural)` 微软晓伊）。
- **`pickBestVoice` 策略**：
  1. 异步监听 `voiceschanged` 事件，确保完整枚举可用音色；
  2. 优先匹配包含 `xiaoxiao`、`xiaoyi`、`Natural` 的中文超自然音色；
  3. 英文模式优先匹配 `Microsoft Jenny Online (Natural)` 与 `Aria`；
  4. 杜绝直接听任操作系统指派老旧离线引擎。
- **声学参数江南化调优**：
  - 中文语速（`rate`）由原先偏快的 `0.95` 放缓至 **`0.88`**，营造文人雅集从容从雅、轻言细语的娓娓道来感；
  - 音调（`pitch`）微调至 **`1.04`**，声线更显清润亲切，避免老旧男/女声的低沉死板。

### 2.2 语音文本口语化净化器（`sanitizeSpeechText`）
在音频合成前，新增纯文本净化流水线：
- 剥离代码块、反引号与 Markdown 标记（`**`、`*`、`#`、`---`）；
- 智能将 `[文字](URL)` 转换为纯文本；
- 剥离列表符号（`-`、`*`、`1.`），避免朗读出“减号、点”；
- 过滤 `（文献线索）`、`（工艺经验）`、`（课程原型）` 等供界面审查的内部注记，使听觉输出完全呈现为面对面优雅对谈的口语文案。

### 2.3 顶栏一键静音与单条优雅点播（`GuidePage.tsx`）
- **顶栏常驻音频胶囊**：
  在对话区域顶栏右侧新增直观状态按钮（`🔊 自动讲解` / `🔇 已静音`），住客点击即可在全局静音与自动朗读之间无缝切换；
- **单条回答随需点播**：
  将原本的“朗读回答”按钮文案与图标升级为：
  - 未播放态：`🔊 听婉娘讲解`
  - 播放中态：`⏹ 暂停讲解`（高亮水碧色，支持口型同步与随时即时打断）。
