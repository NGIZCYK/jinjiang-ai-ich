## 1. 任务背景与核心痛点

阶段 C 实现了流式文本的分句与严格串行 TTS 播放，但数字人的面部表现存在明显瓶颈：
1. **嘴形与发音割裂**：传统方案仅凭“是否在播放”显示一段固定的说话动效，无法根据具体音素（元音、辅音、圆唇、闭口）实时开合；
2. **凭据安全隐患**：若直接在前端配置长期语音 API Key，会导致凭证泄露；
3. **首屏体积膨胀**：重型 Speech SDK 若打包进入首屏，会严重拖慢酒店首页首屏 LCP，违背轻量化原则；
4. **强依赖外部服务导致不可用**：若外部语音服务欠费、断网或未配置密钥，若无优雅的多级自动降级，会导致整个导览语音崩溃。

## 2. 具体实施与模块清单

### 2.1 服务端短期 Token 签发与凭证隔离
- **`web/.env.example`**：
  - 增加 Azure Speech 环境变量占位：`AZURE_SPEECH_KEY`、`AZURE_SPEECH_REGION`、`AZURE_SPEECH_VOICE_ZH`、`AZURE_SPEECH_VOICE_EN`；
- **`web/vite.config.ts`**：
  - 服务端中间件加载 Azure 环境变量，**长期密钥绝不暴露至前端**；
  - 提供 `GET /api/tts/status`：返回当前支持的最高 TTS 模式（`viseme` 或 `browser`）；
  - 提供 `GET /api/tts/token`：当配置了密钥时，服务端向 Azure STS 端点换取短时临时令牌（Token，有效时长 10 分钟）并返回前端；未配置密钥时静默返回 `{ mode: 'browser', token: null }`。

### 2.2 Viseme 收敛映射与帧间线性插值引擎
- **`web/src/lib/tts/visemeMapper.ts`**：
  - **标准参数收敛（任务书 381-389 节）**：
    - 闭口：`mouthOpen = 0, mouthForm = 0`（ID 0 静音、ID 21 p/b/m 闭口唇音）；
    - 小开口：`mouthOpen = 0.2~0.35`（ID 6, 7, 14, 15, 17, 18, 19 等）；
    - 中开口：`mouthOpen = 0.4~0.65`（ID 4, 5, 8, 10, 12, 20 等）；
    - 大开口：`mouthOpen = 0.7~0.85`（ID 1, 2, 3, 9, 11 饱满大元音）；
    - 唇形：圆唇（`mouthForm < 0`，如 ID 3, 7, 8）与展唇（`mouthForm > 0`，如 ID 6, 11, 15）；
  - **毫秒级帧间插值（`interpolateVisemeFrame`）**：在关键帧之间做平滑线性过渡，消除嘴形瞬间突变跳变；末帧超出 150ms 逐渐阻尼回位至 0，杜绝挂嘴；
  - **低幅度节奏动画（`getApproximateFallbackViseme`）**：在浏览器原生 TTS 或无 Viseme 情况下，模拟 3Hz 自然音节语韵（`mouthOpen` 在 0.16~0.34 间微动），并在代码中明确标记为 `approximate fallback`；
  - **复位归零（`getRestViseme`）**：保证停止、暂停与报错时嘴形可靠闭合归零。

### 2.3 动态按需加载 Azure Viseme Provider 与降级工厂
- **`web/src/lib/tts/azureTts.ts`**：
  - `AzureVisemeTtsProvider implements TtsProvider`；
  - **代码分割（Code Splitting）**：采用 `import('microsoft-cognitiveservices-speech-sdk')` 动态导入，构建产物独立拆包为 `microsoft.cognitiveservices.speech.sdk-*.js`，**首页首屏体积零污染**（落实任务书 502 节）；
  - 自动管理 10 分钟临时 Token 续期；
  - 监听 `synthesizer.visemeReceived` 事件，捕获 `event.visemeId` 与 `event.audioOffset / 10000`（毫秒），构建精确时间轴；
  - 纯内存音频合成并转化为标准 Web Audio 播放器，提供毫秒级对齐与极速终止（`< 10ms`）。
- **`web/src/lib/tts/ttsFactory.ts`**：
  - 提供 `detectTtsMode()` 与 `getTtsProvider()`；
  - 形成 **Azure Viseme（级别 1）→ 浏览器原生 TTS（级别 2）→ 静音接待（级别 3）** 的三级坚固回退链。

### 2.4 语音队列 rAF 动画循环与数字人联动
- **`web/src/hooks/useSpeechQueue.ts`**：
  - 内部运行 `requestAnimationFrame` 时间轴循环：在播放期间逐帧根据 `currentTime` 获取精确 `mouthOpen` 与 `mouthForm`；
  - 导出 `mouthOpen: number`、`mouthForm: number`、`ttsMode: 'viseme' | 'browser' | 'unavailable'`；
  - 播放结束、打断、切换语言或组件卸载时立即取消 rAF 并执行 `mouthOpen: 0, mouthForm: 0` 复位。
- **`web/src/components/avatar/StaticAvatar.tsx` & `AvatarStage.tsx`**：
  - 接收口型参数并绑定至 CSS 变量 `--avatar-mouth-open`、`--avatar-mouth-form`；
  - 依据开口度进行颌部/呼吸细微微动，严格遵守 `prefers-reduced-motion`；
  - 为阶段 E 接纳正式 Live2D 预留直通参数绑定通道（`ParamMouthOpenY`、`ParamMouthForm`）。
- **`web/src/pages/GuidePage.tsx`**：
  - 页面接入口型与模式参数；
  - 导览设置面板清晰展示当前语音模式（`Azure Viseme (精确口型同步)` / `浏览器原生语音 (节奏口型回退)` / `语音暂不可用`）。
