## 1. 任务背景与核心痛点

在阶段 B 实现了 DeepSeek SSE 流式文字逐字吐出后，接入语音朗读（TTS）面临以下技术难点：
1. **声音重叠与乱序**：大模型按 token 流式吐字，若直接对每个片段调用浏览器 TTS，会产生严重的声音重叠、乱序或卡死；
2. **标点与停顿不自然**：若机械按逗号切分，句子过短（如“但是，”、“例如，”）会导致声音断续；若按整段切分，必须等待全文生成完毕才能发音，失去流式互动的即时性；
3. **数字、缩写与网址误切**：苏绣工艺包含大量精细数值（如“1.5 丝”、“1/16 丝”），英文包含缩写（如“Dr.”、“e.g.”、“approx.”），普通标点正则容易在小数点处错误分句；
4. **打断延迟与幽灵语音**：用户点击“停止”、切换语言或关闭页面时，如果底层语音无法在 300ms 内可靠打断，会出现人物已停止但后台仍在说话的幽灵现象。

## 2. 具体实施与模块清单

### 2.1 智能分句器与 Markdown 清洗器
- **`web/src/lib/sentenceSegmenter.ts`**：
  - **核心终止符规范**：中文识别 `。！？；\n`，英文识别 `. ! ? ; \n`；
  - **抗误切保护逻辑**：
    - 小数与工艺规格保护：跳过如 `1.5`、`3.14`、`1/16` 中的点与斜杠；
    - 常见英文缩写保护：内置词典（`dr`, `mr`, `mrs`, `ms`, `prof`, `e.g`, `i.e`, `approx`, `etc`, `vs` 等），缩写后接句点时不切分；
    - URL 与网络链接保护：识别 `https://`、`http://` 等网址模式；
  - **自适应长短句控制**：
    - 短句自动合并：中文 < 8 字、英文 < 20 字符时与后续句子自动粘合，避免破碎气泡；
    - 超长句软切分：中文 > 120 字、英文 > 260 字符时优先在逗号、分号或换行处优雅分段，防止单句过长造成语音生成延迟；
  - **语音专用 Markdown 净化**：提供 `cleanMarkdownForSpeech(text)`，自动剔除标题标记（`###`）、粗体（`**`）、超链接语法（保留文字）、代码块及多余空白；
  - **双模式接口**：
    - 静态整段分句：`splitIntoSentences(text, language)`；
    - 流式分块分句：`SentenceSegmenter` 类，支持 `feed(chunk)` 增量输出就绪完整句，流结束调用 `flush()` 冲刷尾部缓存。

### 2.2 TTS Provider 标准接口契约
- **`web/src/lib/tts/types.ts`**：
  - 严格按照任务书 5.3 节定义规范数据结构：
    - `SpeechRequest`：包含 `id`、`text`、`language`、`messageId`；
    - `SpeechPlayback`：包含 `play(): Promise<void>`、`stop(): void`、`visemes?`、`durationMs?`；
    - `TtsProvider`：包含 `readonly mode: 'viseme' | 'browser' | 'unavailable'` 与 `prepare(request, signal): Promise<SpeechPlayback>`。

### 2.3 浏览器原生 TTS Provider 实现
- **`web/src/lib/tts/browserTts.ts`**：
  - 实现 `BrowserTtsProvider implements TtsProvider`；
  - 规范处理浏览器 `SpeechSynthesisUtterance` 的语速（中 0.95，英 0.92）、音调与语种（`zh-CN` / `en-US`）；
  - 完善的生命周期封装：`onstart`、`onend`、`onerror` 与 `AbortSignal` 联动；
  - 提供环境特征检测，在无语音能力环境下自动降级为 `unavailable`。

### 2.4 严格串行语音播放队列 Hook
- **`web/src/hooks/useSpeechQueue.ts`**：
  - **严格单实例串行（FIFO）**：内部维护 `queueRef` 与 `isProcessingRef`，前一句完全播放完毕后才进入下一句，从架构上杜绝声音重叠；
  - **极速打断机制（< 50ms）**：
    - 调用 `stop()` 时立即清空待播队列；
    - 通过当前句专属 `AbortController` 触发当前播放器 `playback.stop()`；
    - 底层兜底执行 `window.speechSynthesis.cancel()`，响应耗时远低于任务书规定的 300ms；
  - **语种与组件生命周期安全**：
    - 语种切换时自动触发 `stop()`，清理旧语言待播与发音，杜绝串语种；
    - 组件卸载（`useEffect` cleanup）时立即调用 `stop()`，不留任何后台幽灵语音；
  - **状态同步**：对外输出 `isPlaying`、`currentSpeechId`、`currentMessageId` 与 `queueLength`。

### 2.5 导览主界面全链路联动
- **`web/src/pages/GuidePage.tsx`**：
  - **解耦直接调用**：完全废弃旧有直接调用浏览器 `speechSynthesis` 的逻辑，全量迁移至 `useSpeechQueue` 与 `SentenceSegmenter`；
  - **流式自动朗读**：
    - 在 `send()` 发送新问题时首先执行 `speechQueue.stop()`；
    - 若开启“自动朗读”，在 SSE `onDelta` 回调中将增量 delta 送入 `segmenter.feed(delta)`，一旦切出完整自然句即刻入队 `speechQueue.enqueue()`，实现“文字还在生成，首句已开始播报”的高效体验；
    - 生成完毕 `onDone` 时调用 `segmenter.flush()` 将末尾未完句子入队；
  - **数字人动作与口型联动**：
    - 将 `speechQueue.isPlaying` 直连 `useAvatarDirector({ isSpeaking: speechQueue.isPlaying })`；
    - 状态机精准运转：`idle → listening → thinking → speaking → idle / paused`；
  - **单条消息手动朗读与停止**：
    - 聊天卡片上的“朗读回答”按钮根据 `speechQueue.isPlaying && speechQueue.currentMessageId === m.id` 动态显示为“朗读回答”或“停止朗读”，并支持随时独立点击打断；
  - **全局控制安全**：
    - 点击“停止”生成按钮时同步中止文本与语音队列；
    - 取消勾选“自动朗读新回复”开关时立即打断当前朗读；
    - 清空会话时清空所有语音队列。
