# 分析看板合并说明

本文说明如何把本次“分析看板”改动合并到同学维护的旧项目中。合并前请先备份双方项目，并关闭正在运行的前端服务。

## 合并目标

合并后项目应具备以下链路：

`婉娘导览匿名意向 → 分析看板客群/ROI 计算 → DeepSeek 运营简报 → 试点、扩大或暂停决策`

其中分析样本是课程合成数据；DeepSeek 密钥只保留在本地 `web/.env`，不应放进压缩包、Git 仓库或聊天记录。

从本次调整后的项目复制到同学的项目中：

| 操作 | 文件 |

| 新增或覆盖 | `web/public/analytics/analytics_snapshot.json` |
| 覆盖 | `web/src/pages/AnalyticsPage.tsx` |
| 新增 | `web/src/lib/analytics.ts` |
| 合并 | `web/src/types.ts` |
| 合并 | `web/src/lib/store.ts` |
| 合并 | `web/src/lib/llm.ts` |

若同学在同一文件中有自己的新改动，不要整份覆盖。请按“二、容易冲突的文件”中的最小改动合并。

## 二、容易冲突的文件及最小合并内容

### `web/src/types.ts`

保留原有类型，再加入：

- `GuidePartyType`；
- `GuideSignal`；
- `AnalyticsSnapshot` 中的 `source`、`sampleSize`、`records`、客群统计字段和方案 `defaults` 字段。

### `web/src/lib/store.ts`

保留同学已有的 Zustand 状态和 localStorage 键，再加入：

- `GUIDE_SIGNALS_KEY = 'jj_guide_signals'`；
- `guideSignals` 状态；
- `addGuideSignal()`；
- `clearGuideSignals()`。

不要改动既有用户、预约、聊天或内容工作台的 state 名称。

### `web/src/lib/llm.ts`

保留同学原有的聊天回复、知识库和 API 调用；只加入 `extractGuideSignal()` 及其 `GuideSignal`、`GuidePartyType` 类型导入。该函数只提取兴趣、时长、预算、同行类型等匿名标签。

### `web/src/pages/GuidePage.tsx`

在用户发送消息的位置保留现有的 `addMessage()` 调用，并在其后加入：

1. 调用 `extractGuideSignal(q, language)`；
2. 若有标签，调用 `addGuideSignal({ ...signal, sourceMessageId: userMessage.id })`；
3. 清空对话时额外调用 `clearGuideSignals()`。

页面提示可说明标签匿名汇总至看板，但不要显示或上传聊天原文。

### `web/vite.config.ts`

保留原有 `/api/chat` 和服务器配置，在同一个本地 API 插件中加入：

- `parseModelJson()`；
- `POST /api/analytics/brief` 路由；
- 该路由从 `DEEPSEEK_API_KEY` 读取密钥，接收聚合后的 `analysis`，调用 DeepSeek 并返回 JSON 简报。

不要使用 `VITE_DEEPSEEK_API_KEY`，因为 `VITE_` 前缀会把变量暴露给浏览器。

### `web/src/pages/AnalyticsPage.tsx`

该文件建议整体覆盖，因为它同时处理：

- Python JSON 快照读取；
- 客群筛选；
- 收入、ROI 和回本期实时计算；
- 可执行经营建议；
- 导览匿名意向汇总；
- DeepSeek 运营简报按钮与展示。

若同学已经修改此页面，先复制其版本作为备份，再逐段合并上述六类功能。

## 三、重新生成分析快照

在合并后项目根目录执行：

```powershell
cd analytics
pip install -r requirements.txt
python analyze.py
```

脚本会同时更新：

```text
analytics/output/analytics_snapshot.json
web/public/analytics/analytics_snapshot.json
```

如果电脑没有 Python，也可以先使用压缩包内已生成的 `web/public/analytics/analytics_snapshot.json` 运行前端；只有修改样本或分析模型后才需要重新运行脚本。

## 四、配置 DeepSeek

在 `web` 目录创建或保留本地文件 `.env`：

```env
DEEPSEEK_API_KEY=你的密钥
DEEPSEEK_MODEL=deepseek-chat
DEEPSEEK_BASE_URL=https://api.deepseek.com
```

合并时不要覆盖同学已有的 `.env`，也不要把 `.env` 发给任何人。若未配置密钥，婉娘导览可保留本地回复，但“生成 AI 运营简报”会提示服务未配置。

## 五、验证清单

1. 在 `web` 目录运行 `npm run dev`，打开 `http://127.0.0.1:5180/analytics`。
2. 页面应显示“Python Pipeline”，且不应请求 `MOCK_ANALYTICS`。
3. 调整客群、时长或兴趣筛选后，匿名样本数和可触达客群规模应变化。
4. 调整转化率、体验课单价或成本后，营收、ROI 和回本期应实时变化。
5. 在“婉娘导览”输入包含体验、时长、预算或同行需求的话，再回到看板，应看到匿名意向汇总。
6. 配置密钥后点击“生成 AI 运营简报”，应返回行动项、扩大门槛和暂停条件。
7. 最后运行：

```powershell
npm run build
```

构建成功即说明 TypeScript 和生产包均通过验证。
