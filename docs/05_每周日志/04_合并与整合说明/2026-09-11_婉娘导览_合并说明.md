# 将婉娘导览更新合并到同学的旧项目

适用场景：你把现在的 `jinjiang-ai-ich` 打包成 ZIP 发给同学，同学需要把婉娘导览的更新合并进自己的旧项目，同时保留其他同学已经完成的页面。

## 合并原则

不要用新 ZIP 直接覆盖同学的整个旧项目文件夹。这样容易覆盖首页、沉浸非遗角、内容工作台、我的体验或分析看板中其他同学的新改动。

应当先解压新 ZIP 到一个单独文件夹，再只合并下面列出的婉娘导览相关文件。合并前，双方都应备份自己的项目文件夹。

## 需要合并的文件

| 新项目中的文件 | 合并目的 | 合并方式 |
| --- | --- | --- |
| `web/src/pages/GuidePage.tsx` | 婉娘聊天界面、API 调用、行程/预约卡片、清除对话按钮 | 若旧项目没有修改导览页，可直接替换；若改过导览页，请以新文件为主逐段合并。 |
| `web/src/lib/llm.ts` | 调用 `/api/chat`、处理回答、情感标签和导览动作 | 合并婉娘相关的类型、`askWanNiang`、`getChatMode` 等逻辑，保留其他人自己添加的无关工具函数。 |
| `web/src/lib/store.ts` | 保存聊天消息、初始问候、去重问候和清除聊天记录 | 合并 `GUIDE_GREETING`、`compactGuideGreeting`、`resetGuideChat` 及其类型定义；不要删除其他业务的 store 状态。 |
| `web/vite.config.ts` | DeepSeek 本地 API 代理、对话提示词、导览动作工具 | 需要仔细合并。保留原有的 Vite 插件和服务器设置，再加入 `loadEnv`、`/api/chat/status`、`/api/chat`、DeepSeek 调用与导览动作逻辑。 |
| `web/.env.example` | 给同学说明本地密钥配置格式 | 可直接替换或补充内容。 |
| `web/.gitignore` | 防止 `web/.env` 被提交或打包 | 确保至少含有 `.env` 和 `.env.local`。 |
| `.env.example` | 项目根目录的配置示例 | 可直接替换或补充内容。 |
| `README.md` | 启动和 DeepSeek 配置说明 | 建议手动合并相关段落，避免覆盖同学补充的说明。 |
| `open-immersive.cmd` | 本机直接打开沉浸角的可选辅助脚本 | 可选，不影响网站从首页导航；同学不需要它时可以不合并。 |

## 推荐操作步骤

1. 将你发出的 ZIP 解压到单独目录，例如 `jinjiang-ai-ich-new`，不要直接解压到旧项目上。
2. 同学先复制自己的旧项目，形成备份，例如 `jinjiang-ai-ich-backup`。
3. 用 VS Code 打开旧项目和 `jinjiang-ai-ich-new` 两个文件夹，逐个比较上表中的文件。
4. 如果某个文件只有你修改过，例如旧项目没有改过 `GuidePage.tsx`，可以直接用新文件替换旧文件。
5. 如果双方都改过同一个文件，不要直接替换。使用 VS Code 的比较/合并功能，把双方内容合在一起：
   - `GuidePage.tsx`：保留同学的页面样式改动，同时保留新版本的 `clearChat`、聊天 API 与“清除对话 · Clean”按钮。
   - `store.ts`：在原有 `AppState` 类型和 store 对象中加入导览聊天的三个成员，不要覆盖预约、内容生成等其他状态。
   - `llm.ts`：保留旧的本地演示回复作为 API 失败时的回退，再加入 API 请求和动作解析。
   - `vite.config.ts`：这是最容易冲突的文件。保留旧项目已有的 `plugins`、端口和其他 server 设置，再把新版的 DeepSeek 路由和导览工具函数放进同一个 `server.configureServer` 中；同一配置文件里只能有一个 `configureServer`。
6. 不要复制 `web/node_modules`、`web/dist`、`web/.env`、日志文件或构建缓存。进入合并后的 `web` 目录后执行 `npm install`，让同学本机重新安装依赖。
7. 在合并后的项目中创建 `web/.env`。从 `web/.env.example` 复制内容，再由项目负责人自行填写自己的 DeepSeek 密钥。不要把真实密钥放进 ZIP、Git 仓库、微信文件或截图。
8. 用项目原有的方式启动开发服务，例如在 `web` 目录执行 `npm run dev` 或 `./start-dev.ps1`，浏览器打开 `http://127.0.0.1:5180/`，再从首页进入“婉娘导览”。
9. 验收以下内容：
   - 左侧显示“当前模式：DeepSeek API”。
   - 任意输入能得到不同的回答，而不是只响应四个快捷问题。
   - 连续补充人数、时长、预算时，婉娘不会重复已经讲过的体验内容。
   - “清除对话 · Clean”会把旧对话恢复为一条初始问候。
   - 生成行程、预约草稿、进入沉浸非遗角的链接能正常显示。

## 出现问题时的检查顺序

1. 页面显示“本地演示回复”：检查 `web/.env` 是否存在、是否填写了 `DEEPSEEK_API_KEY`，并在修改后重启开发服务。
2. 页面显示 API 模式但发送失败：检查网络、密钥状态，以及浏览器开发者工具中的 `/api/chat` 请求响应。
3. 启动报错：在 `web` 目录重新执行 `npm install`，然后执行 `npm run build` 定位 TypeScript 或合并冲突。
4. Git 提示 `.env` 有改动：不要提交它；确认 `web/.gitignore` 中有 `.env`。

## 交付给同学时建议附带的说明

“这次只更新婉娘导览和本地 DeepSeek API。请不要整包覆盖旧项目；按 `Update-20260911.md` 合并 listed 文件。你们需要在自己电脑的 `web/.env` 填写自己的 DeepSeek 密钥，密钥不要发送或提交。”
