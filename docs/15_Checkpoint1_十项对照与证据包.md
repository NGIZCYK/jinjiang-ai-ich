## 三、提交前自查（逐项打勾）

### 内容完整性

- [ ] 十项内容在报告与演示中**都能被找到**（用第一节表格逐行核对）
- [ ] 报告与演示**语言一致**，且与课程确认的语言一致（⛔ 待确认）
- [ ] 参考文献为 APA 格式，且**替换掉模板中的占位条目**，补上实际查阅来源与访问日期

### 真实性

- [ ] 所有 `【PLACEHOLDER: …】` 已替换为真实信息
- [ ] 助教反馈按「团队转述」口径书写，未伪造截图
- [ ] 所有模拟/合成数据均有 `simulated` 或「合成假设」标注
- [ ] 没有一处把「计划做」写成「已经做」

### 演示准备

- [ ] 能现场**走完一条完整用户流程**（不是翻独立页面）
- [ ] 提前准备示例输入；示例账号可正常登录
- [ ] 演示前核对链接权限、页面跳转、按钮；准备截图/录屏备份
- [ ] 明确说明「哪些已能运行、哪些只是原型交互或模拟结果」
- [ ] 全员知道三个核心功能是什么、自己贡献了什么

### 提交

- [ ] 文件名符合 `Group20_Component2_Checkpoint1_<日期>` 规则
- [ ] 由**组长**上传 LMO，全组确认完整、成功、**文件可打开**
- [ ] 确认 Checkpoint 1 Report 与 Draft 1 是否**分别上传**（⛔ 待确认）
- [ ] 确认具体截止时刻与迟到扣分规则（迟到 5%/天，最多 5 天）

## 四、必须向 TA / 课程负责人确认的事项

> Checkpoint Reports 与 Draft 1 的篇幅、语言、时限、上传方式在现有材料中**均未写明**。以下 6 条无法通过阅读手册解决，需直接确认：

1. 报告是否有字数或页数要求？附录与参考文献是否计入？
2. 每组演示多少分钟？是否包含问答？
3. 报告与演示使用什么语言？
4. 具体日期、时段与演示方式？是否只向 assigned Mentor 汇报？是否需要全员到场或发言？
5. 是否需要提交 PPT 或录屏？
6. Checkpoint 1 Report 与 Draft 1 是否分别上传？对应入口与截止时间？

**可直接发送的询问文字：**

> 我们正在准备已延期至 Week 4 末的 Checkpoint 1。请确认：报告是否有字数或页数要求，附录及参考文献是否计入；每组演示多少分钟，是否包含问答；报告和演示使用什么语言；具体日期、时段及演示方式；是否只向 assigned Mentor 汇报，是否需要全员到场或发言；是否需要提交 PPT 或录屏；Checkpoint 1 Report 和 Draft 1 是否分别上传，以及对应入口和截止时间。谢谢。

## 五、7 分钟排练脚本（内部方案，非官方时限）

> 获知每组正式时段后调整。建议额外准备 2–3 分钟答问内容。对应的幻灯片建议 6–8 页。

| 时间 | 内容 | 要说明什么 | 主讲 |
| :--- | :--- | :--- | :--- |
| 0:00–1:00 | 问题与用户 | 谁在什么场景遇到什么问题（用一句中英问题陈述开场） | 【待定】 |
| 1:00–2:00 | 证据与诚实边界 | **主动说明**：已有二手与过程证据，真人测试 Week 4 启动 | 【待定】 |
| 2:00–3:00 | 方案、MVP 与三个核心功能 | 最小版本怎样带来价值，哪些是 MUST | 【待定】 |
| 3:00–5:00 | **点击原型** 走八步动线 | 从用户输入到结果，再到下一步行动 | 【待定】 |
| 5:00–6:00 | 测试与决策（D1–D8） | 哪些反馈/复核导致我们修改、删除或简化 | 【待定】 |
| 6:00–7:00 | 下一步与分工 | 接下来做什么、谁负责、还要验证哪 5 个假设 | 【待定】 |

### 建议准备的追问答案

| 可能的追问 | 我们的回答要点 |
| :--- | :--- |
| 为什么选这个问题？证据来自谁？ | 3 个候选按 5 维度打分，选项 1 得 24/25；证据来源如实分为二手/过程/待补三类 |
| 当前证据能证明什么，还有什么没确认？ | 能证明选题经过结构化比较、内容有来源；**不能**证明严重度已被用户验证 |
| 哪个核心功能最有价值？ | 功能二（意向闭环）——它是唯一把兴趣变成可处理需求的链路 |
| 为什么登录、首页、美化不算核心功能？ | 它们没有「用户输入 → 处理 → 价值」的完整逻辑 |
| MVP 删掉了什么？为什么能按时完成？ | 删掉真实 PMS、支付、3D 全景、Live2D 正式模型；理由见决策 D1–D3 |
| 测试者在哪里困惑？据此改了什么？ | **如实回答：真实用户测试 Week 4 启动**，目前只有内部走查发现的两处修复 |
| 下一阶段每个人负责什么？ | 见报告 §8.1 分工表 |
