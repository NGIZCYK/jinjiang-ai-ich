# 演示脚本与账号

本脚本对应 Supabase 云后端版本。演示展示数字文化体验和演示场次处理流程，不代表真实酒店库存、预约、到场或收入。

> 部署前置：2026-09-19 的线上核验发现批次迁移与新版 Edge Function 尚未上线。第 1、3、8 步涉及 `Study 01` 分配和导览聚合，须先按 [交接文档](HANDOFF_FOR_NEXT_AGENT.md) 完成部署与回归，演示当天再次核验。

## 一、演示前检查

- 启动 `web/start-dev.ps1`（开发端口 5180）或根目录 `启动网站.cmd`（生产预览端口 5181）。
- 确认 Supabase 登录、42 个滚动演示场次及婉娘能力状态可以读取。
- 有效账号和密码由团队负责人通过独立渠道发放，不写入仓库或演示文档。
- 准备一个尚未产生任何记录的住客账号。新账号固定进入 `Demo`。
- 先以运营账号进入 `/operations`，在“测试参与者分配”中把该住客分配到 `Study 01`。产生探索、推荐、意向或导览记录后批次会锁定。
- 分别使用两个浏览器或两台设备登录住客与运营账号，验证状态刷新。

## 二、八步演示动线

| # | 操作 | 向评审证明 |
| :-: | :--- | :--- |
| 1 | 运营在 `/operations` 将一个未开始任务的住客分配到 `Study 01`，住客随后登录 | 服务端批次控制；注册者不能自行污染正式测试数据 |
| 2 | 从首页进入婉娘导览或苏绣艺境 | 清晰的住客入口与八页面信息架构 |
| 3 | 在 `/guide` 输入“我带孩子，下午有 2 小时，预算 150，想体验苏绣” | DeepSeek 流式问答；只把体验、亲子、2 小时、预算等结构化字段写入所属批次，不保存聊天原文 |
| 4 | 在 `/immersive` 选择纹样和配色、比较两种劈丝等级、完成反思题并保存探索卡 | 三步探索任务、真实进度和跨设备保存 |
| 5 | 点击“让婉娘推荐体验”，核对需求卡，保存 90 分钟工坊推荐；进入“我的行程”选择演示场次并主动提交意向 | 规则筛选、AI 解释、显式确认、容量与防重复校验 |
| 6 | 运营在另一浏览器的 `/operations` 筛选 `Study 01`，直接确认名额，再标记“模拟流程已完成” | 角色权限、状态机与双向协同；只有拒绝时必须填写原因 |
| 7 | 住客重新进入 `/my` 或刷新，查看最新状态并提交一次数字流程反馈 | 跨设备同步与一单一评 |
| 8 | 运营在 `/analytics` 选择 `Study 01`，查看漏斗和该批次导览意向汇总，再生成 AI 运营简报 | 观察数据、合成经营假设和运营决策分区；AI 不接收聊天原文 |

价值陈述：把住客的苏绣兴趣转化为可处理的体验意向和按测试批次去重的观察数据，让酒店判断下一轮应继续试点、调整还是暂缓。

## 三、降级说明

| 情形 | 实际表现 |
| :--- | :--- |
| Supabase 环境变量未配置 | 登录与共享保存入口禁用，并显示“共享服务尚未配置”；游客仍可探索和查看规则推荐 |
| Supabase 已配置但网络不可达 | 请求显示失败，不显示虚假成功；恢复网络后重新提交 |
| DeepSeek 不可用或超时 | 导览切换到本地知识回答，规则推荐继续可用 |
| Azure Speech 未配置 | 使用浏览器语音；不可用时保持静音文本体验 |
| Live2D 资产未配置 | 使用静态婉娘形象 |
| 生成过程卡住 | 按 `Esc` 中止生成或朗读 |

## 四、密钥和数据边界

- 浏览器端 `web/.env` 只包含 `VITE_SUPABASE_URL` 和 `VITE_SUPABASE_PUBLISHABLE_KEY`。
- DeepSeek、Azure Speech、service role 和 Supabase 管理 token 不进入前端、文档或仓库。
- 匿名访客的结构化导览标签只保留在当前浏览会话，不进入正式统计。
- 登录住客的结构化标签按账号所属批次保存；运营只能读取聚合结果。
- 有效演示账号由团队负责人单独发放，并在演示结束后轮换运营密码。
