# 演示脚本与账号

本脚本对应 Supabase 云后端版本。演示展示数字文化体验和演示场次处理流程，不代表真实酒店库存、预约、到场或收入。公开展示必须连接独立的演示项目，不得连接保存正式测试数据的项目。

> 发布前置：当前本地修复与待发布构建已经准备，但云端更新和浏览器验收尚未完成。先按 [修复与验收记录](14_课程演示修复与验收记录.md) 核对 Origin、登录后真实 provider、运营密码轮换及双端闭环；不要承诺线上已启用 DeepSeek。

## 一、演示前检查

- 启动 `web/start-dev.ps1`（演示端口 5180）或双击根目录 `启动网站.cmd`（演示端口 5181）；两个入口都会读取被 Git 忽略的 `web/.env.demo.local`。
- 确认 Supabase 登录、42 个滚动演示场次及婉娘能力状态可以读取。
- 有效账号和密码由团队负责人通过独立渠道发放，不写入仓库或演示文档。
- 公开演示登录页仅提供“住客演示”卡，点击只填入账号密码，仍需主动登录。运营人员通过独立渠道获取新密码并手工登录，默认进入“体验管理”。
- 住客卡仅在 `VITE_SHOW_DEMO_ACCOUNTS=true` 且住客变量完整时显示。删除托管环境旧 `VITE_DEMO_OPS_*`；运营密码不进入公开构建。演示构建固定独立后端，后端地址或运营公开变量错误时会中止。
- 准备一个尚未产生任何记录的住客账号。新账号固定进入 `Demo`。
- 常规演练保持 Demo。只有真实试验、参与者同意且登记证据后，才由运营在任务开始前分配 Study 01；活动发生后批次锁定。
- 分别使用两个浏览器或两台设备登录住客与运营账号，验证状态刷新。

## 二、八步演示动线

| # | 操作 | 向评审证明 |
| :-: | :--- | :--- |
| 1 | 住客登录 Demo；仅在正式真人试验时由运营事先分配 Study 01 | 服务端批次控制；注册者不能自行污染正式测试数据 |
| 2 | 从首页进入婉娘导览或苏绣艺境 | 清晰的住客入口与八页面信息架构 |
| 3 | 在 `/guide` 输入“我带孩子，下午有 2 小时，预算 150，想体验苏绣” | 按回复实际标注演示在线或本地回答；仅真实 DeepSeek 连通后展示在线 SSE；只把体验、亲子、2 小时、预算等结构化字段写入所属批次，不保存聊天原文 |
| 4 | 在 `/immersive` 在 02 识线切换四主题、色样与受光，并主动比较两种劈丝等级，再选择纹样、完成反思题并保存探索卡 | 三步探索任务、真实进度和跨设备保存 |
| 5 | 点击“让婉娘推荐体验”，核对需求卡，保存 90 分钟工坊推荐；进入“我的行程”选择演示场次并主动提交意向 | 规则筛选、AI 解释、显式确认、容量与防重复校验 |
| 6 | 运营在另一浏览器的 `/operations` 筛选当前演示批次，直接确认名额，再标记“模拟流程已完成” | 角色权限、状态机与双向协同；只有拒绝时必须填写原因 |
| 7 | 住客重新进入 `/my` 或刷新，查看最新状态并提交一次数字流程反馈 | 跨设备同步与一单一评 |
| 8 | 运营在 `/analytics` 选择 Demo（真人试验则为 Study 01），查看漏斗和该批次导览意向汇总，再按实际模型可用性演示运营简报 | 观察数据、合成经营假设和运营决策分区；AI 不接收聊天原文；Demo 不作为扩大依据 |

价值陈述：把住客的苏绣兴趣转化为可处理的体验意向和按测试批次去重的观察数据，让酒店判断下一轮应继续试点、调整还是暂缓。

## 三、降级说明

| 情形 | 实际表现 |
| :--- | :--- |
| Supabase 环境变量未配置 | 登录与共享保存入口禁用，并显示“共享服务尚未配置”；游客仍可探索和查看规则推荐 |
| Supabase 已配置但网络不可达 | 请求显示失败，不显示虚假成功；恢复网络后重新提交 |
| DeepSeek 不可用或超时 | 导览切换到本地知识回答，规则推荐继续可用 |
| Azure Speech 未配置 | 使用浏览器语音；不可用时保持静音文本体验 |
| Live2D 资产未配置 | 使用静态婉娘形象。**当前实际渲染为 puppet 分层立绘，可见动效为眨眼 + 下颚律动 + 语义表演；口型贴片已停用（素材异源），演示台词不得提"口型同步"** |
| 生成过程卡住 | 按 `Esc` 中止生成或朗读 |

## 四、密钥和数据边界

- 浏览器端 `web/.env` 只包含 `VITE_SUPABASE_URL` 和 `VITE_SUPABASE_PUBLISHABLE_KEY`。
- DeepSeek、Azure Speech、service role 和 Supabase 管理 token 不进入前端、文档或仓库。
- 匿名访客的结构化导览标签只保留在当前浏览会话，不进入正式统计。
- 登录住客的结构化标签按账号所属批次保存；运营只能读取聚合结果。
- 有效演示账号由团队负责人单独发放，当前已公开过的运营密码须在发布前轮换并撤销旧会话。
- 公开演示结束后关闭 `VITE_SHOW_DEMO_ACCOUNTS` 或轮换演示住客密码，并清理独立演示项目中的虚拟意向、处理记录和反馈。
