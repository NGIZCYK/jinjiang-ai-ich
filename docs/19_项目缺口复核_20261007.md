## 2. 当前真实技术缺口

### P0：官网域名仍被 Supabase 拒绝

本轮对独立演示项目 `uxfxhqdfrzkafekrbzcf` 的只读结果：

| 请求 | 返回 |
| --- | --- |
| GET `/functions/v1/concierge/capabilities`，不带 Origin | 200，协议 `2026.09.19-guide-v3` |
| 相同 GET，Origin 为官网 `https://idyllic-bubblegum-1f5a5c.netlify.app` | 403，`Origin not allowed` |
| OPTIONS `/functions/v1/concierge/chat`，带官网 Origin 及常规请求预检头 | 403，`Origin not allowed` |

这会阻止官网浏览器正常调用 concierge 的跨域接口。它不证明 Supabase Auth、数据库 REST/RPC 也失败，因为本轮未登录验证这些独立接口。

当前本地 `supabase/functions/_shared/origins.ts` 已默认允许官网。线上拒绝行为与这份本地源码不一致，需要具有项目权限的成员确认线上源码与 `ALLOWED_ORIGINS`，部署正确的 `concierge` 及共享模块，再复测预检。协议 v3 字符串相同不能证明本次优化代码已上线。

### P0：真实模型能力尚未启用或验收

公开能力接口目前报告 `chat.provider=demo`。这表明线上当前没有声明 DeepSeek 能力；不能把本地服务端代码或静态网站发布作为真实模型运行证据。

需核对服务端 `DEEPSEEK_API_KEY`、模型及端点配置，并登录后测试中文/英文问答、来源信息、流式取消、推荐解释和运营简报。密钥仅进入服务端，不进入浏览器配置、课程报告或仓库。

### P1：云端迁移、权限与业务闭环仍缺验收

迁移 SQL 和数据库回归测试已在仓库，但本轮没有查询线上迁移记录或参与者数据。不能据此认定迁移缺失，也不应直接重复执行数据库迁移或 seed。

应先核对独立演示项目的实际迁移和 RPC 定义，再用两名独立住客与一名运营账号验证：账号数据隔离、Demo/Study 01 批次隔离、探索保存、推荐、意向提交、运营确认/拒绝、跨浏览器状态同步、反馈及看板聚合。公共共享住客账号不适合作为独立真人样本的身份依据。

### P1：凭据处置与 Auth 配置尚无完成证据

新产物不包含运营凭据，且本次 Netlify 构建会清除旧变量对前端构建的覆盖；这并未删除 Netlify 控制台里的旧变量，也未轮换历史已公开过的运营密码或撤销旧会话。

需要核对并完成相关处置，确认运营账号权限，以及 Supabase Auth Site URL、必要的重定向地址和实际注册/登录/退出流程。本轮未修改账号或托管配置。

### P1：真实浏览器验收仍缺记录

需要补齐手机/桌面、四种宽度、中英文、减少动态效果、实际播放/停止/离页取消、连续问题、弱网/断网、图片失败、非法简报输出和 Studio 生成—编辑—人工审核—保存的验收。

当前线上能力为 `tts.provider=browser`、`viseme=false`。浏览器语音是现有降级方案；如果要求 Azure 语音，需要配置服务端 Speech key/region 并实测。Azure、真实 Live2D 和精确口型不应自动列为 MVP 必须新增项。

### P2：文化来源及资产授权尚不完整

`docs/02_非遗内容与来源.md` 仍主要列来源类别；共享知识卡包含“正式发布前补录链接与访问日期”“待补录具体书目与页码”。需要补全可追溯条目、访问日期/页码、素材作者与许可，以及必要的工艺专家复核。

### P2：后续维护流程

当前 Netlify 自动执行 Python 测试、分析、TypeScript/前端构建和产物检查，但没有自动执行 `npm test` 的 127 项前端回归。仓库也未见独立 GitHub Actions 工作流或 ESLint 配置。这是可后补的维护项，不是本次已成功发布的阻碍。

## 5. 不应作为“必补功能”的项目

当前阶段无需仅为了填旧报告而恢复 A-Frame/3D、真实 Live2D 或旧口型贴片，也不必新增支付/PMS、防伪雅凭、运营自由搜索排序、茶艺交叉推荐、聊天历史数据库或 Studio 在线 LLM 生成。它们应按目标和已承诺的交付范围另行取舍；现有报告应准确描述二维艺境、分层立绘、规则模板和意向流程。

1. 确认并部署 Supabase 新函数，修复官网 Origin 被拒绝的问题。
