# 登录状态修复（2026-10-28）

## 行为变化

- 登录会话仅保留在当前页面内存中。重新打开或刷新网站从未登录开始，不恢复浏览器中旧的运营账号会话；站内导航保留当前登录。
- 住客和运营快捷登录卡片继续保留，点击填入后由用户提交登录。
- 登录事件和显式登录共享身份加载过程，重复事件不再清空已加载身份；过期的排队事件不再覆盖新的登录状态。
- 退出时立即清理页面身份，资料加载失败时退出加载状态并显示错误。
- “我的行程”在身份清空时安全渲染，避免退出期间访问空用户对象导致页面崩溃。

## 本地验证

- 199 项前端测试全部通过，包含旧持久会话忽略、重复登录事件、退出后再次登录、退出期间未完成请求和资料请求失败的回归测试。
- TypeScript 检查、演示构建及演示产物检查通过。
- Edge 无界面浏览器验证：预置旧运营会话仍显示未登录；连续 5 次住客/运营登录退出；登录后刷新恢复未登录；未捕获页面异常为 0。
- 浏览器验证使用模拟 Supabase 响应，未修改线上账号或业务数据。这项验证覆盖页面登录状态流转，不代替真实后台可用性验收。

## 发布

前端更新经 GitHub main 分支触发 Netlify 构建；本次无数据库迁移或后台函数修改。

## 第二次修复：真实数据导致的运营页面崩溃

用户反馈第一次更新后仍出现空白。在官网使用真实演示运营账号复现了 `TypeError: o.map is not a function`，堆栈定位到运营页面的反馈渲染。数据库 `feedback.booking_id` 是主键，其嵌入查询返回单个对象或 null，前端原先误声明为数组并调用 `.map()`。第一次浏览器检查使用空业务数据，未覆盖这条路径，不能视为真实业务验收。

- 将反馈类型和运营、住客页面读取方式修正为单对象关系；已有反馈正确显示，不再出现重复提交表单。
- 按最新要求，运营和住客登录成功均进入 `/` 首页，不使用旧的角色默认页面或 `next` 查询参数跳转。
- 页面内容增加错误边界，局部渲染异常时保留导航，提供错误提示、返回首页及重试入口。
- 新增真实结构的页面渲染回归测试：运营页面已有反馈、住客页面已有反馈、反馈为 null。总计 202 项测试通过；演示构建及产物检查通过。
- 本地生产构建连接真实后台，验证了运营账号读取 3 条意向（其中 1 条包含反馈对象）、住客账号读取 2 条意向；两个账号都先进入首页，随后进入体验管理或我的行程，未再出现原报错。只登录和读取已有数据，未新增、修改或删除业务记录。
