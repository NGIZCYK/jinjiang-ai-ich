# 课程演示双账号恢复 · 2026-10-07

用户明确要求改回原有格式：一个运营账号、一个住客账号，网站仅用于课程演示。本次调整以该要求为准，替代此前“只公开住客、运营手工登录”的入口设计。

## 修改

- 登录页恢复“住客演示”和“运营演示”两张卡片，桌面并列、手机单列；中文与英文均支持。
- 点击卡片填入现有新项目账号的邮箱和密码，仍需点击“登录并继续”。未创建新账号、未修改数据库角色或已有业务记录。
- 继续连接独立演示项目 `jhosvgldwgndpudwentv`。两个预设已在 `web/.env.demo` 声明，Netlify 构建使用仓库配置。
- 构建检查更新为要求两个演示账号完整、确认两组预设进入产物；只允许声明的演示凭据，服务端管理密钥继续禁止进入产物。
- 真实点击运营登录时发现身份加载竞态，导致角色尚未加载就默认跳入住客行程页。`store.ts` 现在合并同一用户正在进行的身份加载，等待角色确定再跳转。
- 住客默认进入 `/my`，运营默认进入 `/operations`；合法的显式 `next` 继续保留。

- TypeScript/Vite 演示构建通过，六项发布产物检查全部通过。
