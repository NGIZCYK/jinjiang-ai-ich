## P0 — 演示前必须修（合计约 2 小时，不含部署等待）

### ☐ P0-1 统一前后端 API 版本常量，并让 `stale` 不再否决在线能力

- **问题**：客户端与服务端版本字符串不一致，导致 `stale` 恒为 `true`，页面显示假"服务已过期"横幅，且聊天模式被降级为 `fallback`。
- **位置**：
  - `web/src/lib/llm.ts:205` — `GUIDE_API_VERSION = '2026.09.15-guide-v2'`
  - `supabase/functions/concierge/index.ts:3` — `API_VERSION='2026.09.19-guide-v3'`
  - `web/src/lib/llm.ts:249` — `stale: apiVersion !== GUIDE_API_VERSION`
  - `web/src/lib/llm.ts:262-266` — `getChatMode()` 在 `stale` 时直接返回 `'fallback'`
- **修法**：
  1. 客户端常量改为 `'2026.09.19-guide-v3'`（以服务端为准）。
  2. 把 `getChatMode()` 的判据从 `stale` 改为**能力探测**：只要 `capabilities.chat.provider === 'deepseek'` 就返回 `'deepseek'`；`stale` 仅用于 UI 提示，不否决能力。
  3. 顺手确认 UI 横幅文案（`web/src/pages/GuidePage.tsx:245,552` 附近）在 `stale` 为真时只提示、不误导为"必须重启"。
- **验收**：本地起服务 → 打开 `/guide` → 无过期横幅；`getChatMode()` 返回 `'deepseek'`（可在 console 调 `getChatMode()` 验证）。
- **工作量**：30 分钟。

## P1 — 影响技术价值评分与可信度

### ☑ P1-1 数字人口型：已停用贴片，改为下颚律动（2026-09-26 完成）

**状态：✅ 已完成**（采用"证伪 → 停用 → 下颚律动替代"路径，非原 A/B 二选一）

- **原问题**：完整的口型链路被产出，但没有一个渲染器消费它——婉娘可见动作只有眨眼。
- **新增的关键事实（证伪实验结论）**：嘴部盒位置**本来就是对的**（`cx512/cy432` 恰好覆盖嘴部 y[384,480]），
  6 组参数组合（盒子现状/加宽/加宽加高 × 抠图阈值现状/收紧 × 色彩校正 0.85/1.0）**全部失败**：
  现状组合出现原图下唇透出的"双嘴"，加宽出现矩形色块边界，加宽加高则暖色块覆盖至鼻底与颏部。
  根因是 `raw/mouths.png` 与 `raw/base.png` **异源**，`color_match` 仅做肤色均值平移，无法消除色域差异。
  → **原 A 方案（复用 `selectMouthCell` 渲染贴片）已被证伪，不可行。**
- **实际处置**：
  1. 停用并删除口型贴片代码与资产（`MOUTH_*`、`selectMouthCell`、`restMouthCell`、`mouthHysteresisMs`、`mouths.webp`）；
  2. 新增 `.puppet-jaw` 层：`PuppetAvatar` 把 `mouthOpen` **直写 CSS 变量** `--jaw-open`（不经 React state，
     规避 rAF 60fps 重渲染），讲话时 `translateY(≤1.4px) + scaleY(≤1.004)`；`puppet-nod` 幅度 1px → 1.6px；
  3. `StaticAvatar` 不再接收无用嘴部参数；`Live2DAvatar` 的 `setParameters` 契约保持不变；
  4. 对外口径统一为"眨眼 + 下颚律动 + 语义表演"，撤下"口型同步"。
- **证据存档**：`docs/evidence/mouth-sprite-falsification/`（`speak_aa` 与 `warm` 两张对比图 + 参数报告）。
- **验收结果**：`tsc -b` 退出码 0；22 项模块断言全绿；单测由 50 例减为 41 例（删除 9 例失效用例）。
- **复核记录**：2026-09-26 · 由本次会话执行

### ☑ P1-2 A-Frame / 3D 死代码：已清理，不重建（2026-09-26 完成）

**状态：✅ 已完成**（采用原 A 方案：清理）

- **原问题**：1.33 MB 未使用的 vendor 包 + 类型桩 + 死模块 + 26 MB 零引用全景，造成"想做成 3D 但没做完"的印象。

  8K 等距柱状图在全屏约 90° 视口下**有效像素仅约 2048px 宽**，与一张 2K 平面图等强，近看必然偏软；
  这是等距柱状投影的固有上限，不是分辨率没买够。叠加 AI 生成缺少实拍质感，在空间沉浸语境下被放大。
  团队原判断见 `docs/05_每周日志/02_成员工作日志/2026-09-13_苏绣工坊与长卷微距重构.md:26`。
- **已删除**：

  - `web/src/aframe.d.ts`（15 个 JSX intrinsic + `window.AFRAME`）
  - `web/src/lib/textures.ts`（10.9 KB，零 import）
  - `web/src/index.css` 的 `.immersive-canvas-shell`、`.immersive-canvas-shell > a-scene`、`.immersive-panorama-poster`（含 `.is-ready`）
  - `web/public/assets/lobby-*` 全部 14 个（含 `lobby-concierge-360.jpg`、`lobby-heritage-360-{4k,8k,preview}-v2/v3/v4`、三个 `-backup`、`-source-v3.png`，共 25.95 MB）

- **口径**：对外统称"苏绣艺境"，**不再提 A-Frame / 3D**。若未来重启 3D，需新制资产（实拍全景或 3DGS），不要指望恢复已删文件。
